# Contributing to Rego Syntax Support

First off, thank you for considering contributing to Rego Syntax Support!

## Code of Conduct

By participating in this project, you are expected to uphold our Code of Conduct: be respectful, inclusive, and constructive.

## How Can I Contribute?

### Reporting Bugs

Before creating bug reports, please check the existing issues. When creating a bug report, include:

- **Clear title** describing the issue
- **Steps to reproduce** the behavior
- **Expected behavior** vs actual behavior
- **Screenshots** if applicable
- **Environment details**: VS Code version, OS, extension version

### Suggesting Features

Feature suggestions are welcome! Please include:

- **Use case**: Why is this feature needed?
- **Proposed solution**: How should it work?
- **Alternatives considered**: Other approaches you've thought of

### Pull Requests

1. **Fork** the repository
2. **Clone** your fork locally
3. **Create a branch** for your feature/fix: `git checkout -b feature/my-feature`
4. **Make your changes** following our coding standards
5. **Test** your changes thoroughly
6. **Commit** with a clear message: `git commit -m "feat: add amazing feature"`
7. **Push** to your fork: `git push origin feature/my-feature`
8. **Open a Pull Request** against the `main` branch

## Development Setup

### Prerequisites

- Node.js 22 or later (required by `@vscode/vsce` 4)
- VS Code 1.85 or later
- Optional: [OPA](https://www.openpolicyagent.org/docs#running-opa) 1.22 to run `opa parse` locally

### Getting Started

```bash
git clone https://github.com/adamaKomi/rego-syntax-support.git
cd rego-syntax-support
npm ci            # also compiles the TypeScript tests (npm "prepare" script)
```

Press `F5` in VS Code ("Run Extension") to open an Extension Development Host with the extension loaded.

### Project Structure

```
├── scripts/
│   ├── grammar/                # SOURCES of the grammars (edit these)
│   │   ├── rego.js
│   │   ├── injection-yaml.js
│   │   ├── injection-markdown.js
│   │   └── opa-builtins.json   # generated by update-builtins.js
│   ├── build-grammars.js       # scripts/grammar/*.js -> syntaxes/*.json
│   ├── update-builtins.js      # OPA capabilities -> opa-builtins.json
│   ├── dump-tokens.js          # debug: print the tokens of a file
│   └── show-assertion-targets.js
├── syntaxes/                   # GENERATED grammars shipped in the extension
├── languages/                  # language configuration (comments, brackets, indentation)
├── snippets/                   # snippets
├── src/test/
│   ├── unit/                   # Node-only tests (npm run test:unit)
│   └── suite/                  # tests inside VS Code (npm run test:integration)
└── test/
    ├── grammar/                # token assertions for .rego
    ├── embedded/               # token assertions for Rego in YAML and Markdown
    ├── fixtures/               # valid Rego v1 files (must never be flagged invalid)
    ├── integration/            # files opened by the integration tests
    └── vendor/vscode-grammars/ # VS Code's YAML and Markdown grammars (tests only)
```

The extension is purely declarative (no `main`), which keeps it compatible with VS Code for the Web.
Do not add runtime code unless a feature really needs it.

### Coding Standards

- **TypeScript** (tests): strict mode, Prettier, ESLint (`npm run format`, `npm run lint`)
- **Commits**: [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, ...)

### Testing

```bash
npm test                  # compile + lint + unit tests + grammar assertions
npm run test:integration  # downloads VS Code and runs src/test/suite inside it
```

CI also runs `opa parse` on the fixtures and on every expanded snippet, and the integration tests on
Linux, Windows, macOS and on the oldest supported VS Code (1.85).

### Modifying the Grammar

1. Edit `scripts/grammar/*.js`, then run `npm run build:grammars`.
2. Add assertions in `test/grammar/*.test.rego` (or `test/embedded/*`), including negative ones
   (`#   ^^^ - scope`). Check where the carets point with `node scripts/show-assertion-targets.js <file>`.
3. Run `npm test`.
4. Commit the sources **and** the regenerated `syntaxes/*.json`.

See [GRAMMAR.md](GRAMMAR.md) for the scopes and the design of the YAML/Markdown injections.

### Updating the built-in functions for a new OPA release

```bash
npm run update:builtins -- v1.23.0
npm run build:grammars
npm test
```

Then update `OPA_VERSION` in `.github/workflows/ci.yml` so CI checks against the same release.

## Release Process

1. Update `version` in `package.json` and add a section to `CHANGELOG.md` (a unit test checks it).
2. Merge to `main`.
3. Tag and push: `git tag v0.x.y && git push origin v0.x.y`.
4. The Release workflow checks that the tag matches `package.json`, runs the tests, builds the VSIX once
   and publishes that file to GitHub Releases, the VS Code Marketplace (Trusted Publishing, see
   [PUBLISHING.md](PUBLISHING.md)) and Open VSX (Trusted Publishing too). Tags with a suffix (`v0.3.0-rc.1`) only
   create a GitHub pre-release.
